Folio 是什么？

在 eat 里，给一份成果一个可持续分享的网页入口。

它可以是一页说明、一组演示，也可以是一份带交互的报告。读者打开链接即可阅读和体验，并围绕页面内容留下反馈；你可以持续发布新版，也可以保留某次发布的快照。

01 /

从你想分享的事开始。

不必等到“做完一个大项目”。一个值得让别人知道的进展，就可以成为起点。

CHANGELOG适合持续更新

让变化，被真正理解。

上线一个功能、改进一段流程、完成一次迭代。把“我做了什么”写成“这对你有什么用”，让同事知道发生了什么，也知道接下来能做什么。

一份有用的更新，可以讲清楚

  1. 变化这次新增、改进或修复了什么？
  2. 影响谁会受益？使用方式有什么变化？
  3. 下一步在哪里体验？希望收到哪方面反馈？

适用例子：个人工作进展、产品更新、内部工具迭代、团队月度成果。

内容结构示例

这次更新，让什么更好了？

改进

用一张前后对比，说明这次变化。

影响

告诉使用者：这会怎样改变你的工作。

体验

附上入口，并提出一个具体的反馈问题。

同一个 Folio 持续更新；发布历史保留每次交付的样子。

Folio 在这里的价值：让进展拥有固定入口，配上截图、演示和可追踪的反馈。

RESEARCH适合结论与证据一起呈现

让发现，走出研究过程。

做完一次用户访谈、技术调研、竞品比较或数据分析，把零散材料整理成别人能快速理解的结论。读者先看到判断，再按需要深入证据。

把研究写成别人能用的成果

  1. 问题与结论研究了什么？最重要的发现是什么？
  2. 证据与边界依据来自哪里？哪些情况还不能下结论？
  3. 建议与材料建议采取什么行动？如何查阅原始来源？

适用例子：技术选型报告、实验结果、用户洞察、行业专题研究。

推荐阅读层次

先读

一个核心结论

让读者先知道，这份研究回答了什么。

再看

支持它的证据

图表、方法、样本说明与来源链接。

最后

可以怎么行动

建议、限制，以及还需要验证的问题。

Folio 在这里的价值：把长报告组织成分层阅读的页面，让图表和结论在同一处被讨论。

IDEAS适合有上下文的异步讨论

让想法，有被接住的机会。

当一条群消息讲不清你的观察，给想法留一个完整的空间。它可以尚未成熟，但需要说明问题、你的判断，以及你希望大家一起思考什么。

一个值得讨论的想法，需要

  1. 背景你观察到了什么？为什么值得关注？
  2. 主张你的判断或提议是什么？有哪些假设？
  3. 讨论入口希望大家挑战哪个点，或补充哪类例子？

适用例子：流程改进建议、产品方向思考、工作方法、一次阅读后的观点。

提问方式示例

“大家觉得怎么样？”

↓
“如果把这一步移到更早，
会减少哪些等待，
又可能增加什么成本？”

让问题具体一点，让读者更容易参与。明确标注“探索中”，不把假设写成定论。

Folio 在这里的价值：让想法保留上下文，讨论能够关联到具体段落和当时的版本。

INTERACTIVE DEMO适合让人亲手体验

有些事，试一下更明白。

分享一个界面原型、一个计算器，或一张能切换条件的图表。让读者自己点一点、改一改参数，比用多张截图解释状态变化更直接。

一次可理解的体验，应该包含

  1. 体验目标请读者尝试哪个任务或问题？
  2. 可操作内容哪些地方可以点击、输入或切换？
  3. 演示边界哪些是假设参数，哪些能力还没实现？

适用例子：设计原型、方案比较器、静态数据可视化、轻量教学工具。

可交互示例 · 假设参数

小改进，能省多少重复工作？

40分钟 / 周

假设每次节省 5 分钟，仅演示交互。拖动滑块，观察结果变化。它不是业务数据。

Folio 在这里的价值：直接交付可运行的静态网页体验。需要后端、数据库或长期业务服务时，使用 eat 应用部署。

RETROSPECTIVE适合留下可复用的经验

让一次经历，帮助下一次。

项目结束、实验收尾，或解决了一个复杂问题后，把当时的判断和取舍留下来。比“我们做完了”更有价值的是：后来的人能从中学到什么。

让复盘超越工作流水账

  1. 目标与结果想解决什么？实际发生了什么？
  2. 关键取舍当时知道什么？为什么这样选择？
  3. 可复用经验哪些方法值得保留？下次会怎样改变？

适用例子：项目回顾、一次排障的经验、活动总结、试验复盘。

复盘叙事示例

起点

我们遇到了什么问题

选择

有哪些方案，为什么选这一条

结果

哪些有效，哪些没有达到预期

带走

给下一位实践者的具体建议

把“当时的上下文”一起留下，经验才有适用边界。

Folio 在这里的价值：把过程、材料与经验编排成可回看的成果；需要引用当时交付时，可分享版本地址。

GUIDEBOOK适合反复被问到的知识

把反复解释，变成一次好说明。

当同一个问题需要一遍遍回答，整理成能自助理解的指南。围绕读者遇到的任务组织内容，必要时加入演示、对照表或自查问题。

从读者的问题组织一份指南

  1. 谁会用到面向什么人，解决哪一种困惑？
  2. 如何判断遇到不同情况，应该怎么选择？
  3. 遇到问题去哪里查更多材料、反馈或找负责人？

适用例子：新人入门、工具使用场景、团队方法、常见问题说明。

眼前就是一个例子

这份指南，
本身就是一个 Folio。

你可以按场景阅读、切换示例，甚至操作一个小演示。内容更新后，入口仍然保持不变。

如果你有建议，也可以通过页面上的评论入口提出。

Folio 在这里的价值：为常用知识提供经过组织的阅读入口，让每次转发都指向持续维护的内容。

02 /

已经能发文档，
为什么还用 Folio？

选择的关键，是你希望别人如何理解和使用这份内容。

当你需要自由安排阅读顺序、把内容做成可操作的体验、交付一个可以持续更新的页面，Folio 就有了价值。

共享文档也能发链接、评论和保留版本。Folio 的吸引力，在于以网页的形式呈现成果：文字、图表、演示和交互，可以围绕读者的需要一起设计。

按读者需求选择 Folio 或共享文档
你现在需要……Folio共享文档
呈现一份成果自定义页面、演示和分层阅读，适合组织好的交付。快速整理和阅读文字，适合日常说明与协作材料。
让别人亲手体验可以承载静态原型、参数切换、图表和轻量工具。通常通过截图、附件或外部链接辅助说明。
多人一起改正文由作者修改内容并发布新版，适合收集反馈后迭代。实时共同起草、逐句修改通常更方便。
持续分享和回看固定入口展示当前版，版本地址保留某次发布快照。共享链接和版本历史也能满足日常协作需要。
围绕内容讨论可评论页面、元素或区域；评论关联浏览时的版本。适合文字批注与编辑讨论，具体能力取决于工具。

一起把内容写出来先用共享文档。

→

把成果讲清楚、交给别人体验可以做成 Folio。

两者可以配合：文档保留协作过程和详细材料，Folio 呈现结论、关键证据和体验入口。简单的文字通知，直接发消息或文档就足够。

03 /

分享之后，交流才开始。

给读者一个入口，也为后续的讨论与更新留下位置。

↗

一个入口，持续更新

用固定地址分享当前内容。开会、复盘或引用某次交付时，可以改用版本地址，让大家看到同一份快照。

↳

对着内容，具体讨论

读者可以评论整页、某个元素或一块区域。每条评论保留浏览版本，后续仍能回到当时的上下文。

◎

分享给合适的人

默认仅 eat 登录用户可看，也可选择公开或密码访问。公开和密码访问降低阅读门槛，发表评论仍需 eat 登录。

先有合适的内容，再选择载体。

Folio 发布的是静态网页成果；它不会自动替你完成研究、生成可信数据或保存源工程。需要持续维护时，请保留自己的内容和工程文件。
