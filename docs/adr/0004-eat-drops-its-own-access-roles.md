# EAT 自己清理为数据库权限建的角色

历史决策 13 规定平台不删库、不删账号，需要执行 DROP 的由管理员手动完成。数据库权限用到的角色是一个例外：

- **删除外部库的登记时**：EAT 删除这个库的只读组和读写组两个组角色。
- **删除实例时**：EAT 删除这个实例上的个人登录角色。

两种删除都要求相关授权已经全部撤销。如果某个角色名下还有对象，EAT 会停下来报告，不执行 `DROP OWNED`。库本身和分配出去的 owner 账号仍然永远不删。

这样做的原因：这些角色只承载访问配置，不承载数据。如果不清理，用户的数据库里会留下一堆 `eat-*` 角色；以后重新登记同一个库或实例时，还会和这些残留角色重名，被「不接管来源不明的资源」这条规则拒绝。

阿里云接入删除时同理：EAT 清理它在该云账号里建的、并且 OSS 不再使用的 RAM 用户和 Key。
