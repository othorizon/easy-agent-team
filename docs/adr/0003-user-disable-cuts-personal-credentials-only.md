# 停用 EAT 用户只切断个人凭证，不动分配出去的 owner 账号

停用一个 EAT 用户时，要切断他的个人凭证：他在每个云账号里的全部 AccessKey 都设为 Inactive，策略绑定保持不动；他在每个数据库实例上的个人登录角色改为 NOLOGIN，并断开已有会话。分配出去的 owner 账号（EAT 建库时随库创建的那个账号）不做任何改动，只在页面上标记「Owner 已停用」。owner 账号属于应用连接数据库用的资源，独立于个人授权管理，避免停用负责人时连带切断该资源的服务连接。

## Considered Options

- **停用时把 owner 账号也改为 NOLOGIN**：这样负责人一离职，用这个库的线上应用就会断掉。
- **停用时解绑全部阿里云策略**：恢复用户时要逐条重新绑定，多出一类可能失败的操作。RAM 本来就没有「停用用户」的接口，停用全部 Key 就已经等于停用了这个用户。

## Consequences

- **owner 密码仍可登录**：离开的人如果本地存过 owner 账号的密码，仍然可以登录数据库。要彻底收回，需要管理员先改好应用的配置，再手动轮换这个密码。
- **必须向用户说明个人凭证的影响范围**：数据库的控制台、CLI 和平台指南说明停用用户、撤销授权会中断相应连接，重置密码后需更新连接配置。数据库个人凭证不再限定为临时使用；外部库目前没有独立的应用凭证申请入口。阿里云个人凭证仍只供本人临时使用，不配置到线上服务。
- **恢复时只启用一把 Key**：恢复用户时，只重新启用 EAT 管理的那把 Key。有人在控制台手动给这个 RAM 用户建的 Key，恢复后仍保持停用。
