# 每人在每个 PostgreSQL 实例上只有一个个人登录角色

数据库权限的个人身份按实例（集群）建立，角色名为 `eat-<UUID>`。同一实例上的所有库共用这一个角色和一套密码。至于能访问哪些库、能做什么，靠这个角色加入了哪些库的只读组或读写组来决定（组角色是 NOLOGIN 的）。原因有三：PostgreSQL 的登录角色本来就属于整个集群；如果按库建号，角色名里就得带上库的标识，个人凭证会随库的数量一起增长；`eat db run` 也得为每个库分别管一份密码。

## Consequences

- **库之间的隔离要靠 CONNECT 权限**：同一个角色在实例上的每个库都存在，所以隔离不能靠「没有这个账号」。PostgreSQL 默认把每个库的 CONNECT 授给 PUBLIC。因此 EAT 建的库开放申请时，要收回 PUBLIC 的 CONNECT（PG 14 及更早的版本，还要收回 public schema 上 PUBLIC 的 CREATE）。外部库只提示，不替用户修改。
- **重置密码影响整个实例**：一个人重置个人密码，他在这个实例上所有库的授权都会改用新密码。
- **授权就是组成员关系**：授予就是把个人角色加入组角色。撤销或降级时，还要同时终止这个角色在该库上的会话，否则已经建立的连接会继续保有旧的权限。
