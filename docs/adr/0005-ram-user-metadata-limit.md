# RAM 个人身份备注保留身份标记，超长邮箱截断显示

RAM 的 [CreateUser](https://help.aliyun.com/en/ram/developer-reference/api-ram-2015-05-01-createuser) 和 UpdateUser 将备注限制为 128 个字符。EAT 用户邮箱可能长于剩余空间，所以“备注含完整 EAT 用户 ID 和邮箱”无法对任意邮箱同时成立。

按用户最新确认，备注格式为 `EAT:<身份标记>:<邮箱>`，去掉重复的 EAT 用户 UUID。身份标记继续使用本地个人身份 UUID 的紧凑随机标识，完整保留；只在 RAM 备注中把超出空间的邮箱截断，并追加单字符省略号 `…`，总长不超过 128 字符。按 Unicode 字符截断，避免切断字符；长度不超过限制时完整保留邮箱。EAT 数据库中的邮箱始终保留完整值。此格式覆盖此前“备注同时保留完整用户 ID”的决定。

归属校验匹配完整的 `EAT:<身份标记>:` 前缀，并核对已持久化的云端 UserId。邮箱属于展示资料，不参与归属判断；用户改名或改邮箱后，下次执行授权会更新 RAM 显示名和备注。已有旧格式备注共享同一个身份标记前缀，下次确保身份时自然更新为新格式，不另做云端迁移。

## Considered Options

- **因邮箱过长拒绝授权**：邮箱长度并不改变用户是否有权获得权限点，会阻止正常授权。
- **继续在备注中重复 EAT 用户 UUID**：RAM 用户名已经包含完整 EAT 用户 UUID，会额外占用邮箱展示空间，不采用。
- **缩短身份标记**：会削弱来源验证，不采用。
- **修改 EAT 邮箱**：会损失平台资料，不采用。

## Consequences

- RAM 控制台里长邮箱可能只显示前缀和省略号，完整邮箱从 EAT 查阅。
- 名称相同但来源标记或已保存的云端 UserId 不符时仍拒绝接管；截断不影响归属验证。
- RAM 内存测试实现也执行备注、显示名的 128 字符限制，防止测试掩盖真实云约束。
