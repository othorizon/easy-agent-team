# 阿里云个人身份由统一身份层管理，OSS 身份改名迁入

阿里云权限需要每个 EAT 用户在每个云账号里有一个 RAM 用户和一把 AccessKey。OSS 空间却已经为每个人建了一个 OSS 专用的 RAM 用户（`eat-oss-<实例>-<UUID>`）。我们决定新建一个统一身份层，以「云账号 ID + EAT 用户 ID」为唯一键，RAM 用户名固定为 `eat-<UUID>`，由 OSS 和阿里云权限共用。OSS 现有的身份用 RAM 的改名接口迁入，AccessKey 保持不变，所以已经发出去的 OSS Key 不受影响。OSS 只保留空间、聚合策略和 Bucket 公开读。

## Considered Options

- **两套身份并存**：同一个人在同一个云账号里会有两个 RAM 用户、两把 Key，停用一个人时要切断两处。
- **为 OSS 用户重建身份**：换成新 RAM 用户就要发新 Key，所有已经发出的 OSS Key 都会作废。
- **把每个 OSS 空间拆成独立的权限点**：OSS 本来就能通过改写聚合策略来逐个回收空间，拆开后只会多出更多策略，还要挤占每个 RAM 用户最多 10 条自定义策略的配额。

## Consequences

- **空空间改为解绑**：用户名下一个空间都没有时，改为解绑聚合策略，不再写入 `Deny oss:*`。显式 Deny 的优先级最高，会把同一云账号里的 OSS 共享权限一起挡掉。
- **重置 Key 影响两处**：重置一把 Key，OSS 空间和阿里云权限都会受影响，执行前要提示。
- **迁移在先**：OSS 所在的云账号，要等迁移完成后才能接入阿里云权限。
- **不受开关控制**：统一身份层不受「阿里云权限」功能开关控制，OSS 用自己的管理凭证调用它。
